\section{1. Executive Summary \& Problem Statement}
The Stores \& Purchase (S\&P) Department at Gautam Buddha University manages thousands of consumable and capital inventory items across 8 academic schools (ICT, Engineering, Biotechnology, Management, Humanities, Vocational Studies, Law) and administrative divisions. 

Prior manual workflows suffered from:
\begin{itemize}[noitemsep]
    \item \textbf{Stock Ledger Discrepancies:} Paper-based tracking risked negative inventory balances and unverified physical counts.
    \item \textbf{Procurement Lapses:} Purchase orders raised without formal administrative requisition approval.
    \item \textbf{Delayed Condemnations:} Damaged or expired materials remaining on books without formal Director sanction.
    \item \textbf{Audit Deficits:} Difficulty in tracking immutable chronological histories of storekeeper dispatches and managerial approvals.
\end{itemize}

\textbf{Solution:} A full-stack web application implementing strict role-based access control (RBAC), real-time stock ledgering, multi-line requisition workflows, purchase orders tied to approved indents, Goods Receipt Notes (GRN) with partial deliveries, and Director-sanctioned write-offs.

\section{2. System Architecture \& Stack}
\begin{itemize}[noitemsep]
    \item \textbf{Frontend:} React 18, Vite 6, Tailwind CSS, React Router v6, Recharts, Lucide Icons.
    \item \textbf{Backend:} Python 3.14+, FastAPI, SQLAlchemy 2.0 ORM, Pydantic v2.
    \item \textbf{Database:} SQLite (local development) / MySQL (TiDB Cloud Serverless or Aiven in production via PyMySQL with TLS/SSL).
    \item \textbf{Authentication:} JWT (12-hour expiry), Bcrypt password hashing.
    \item \textbf{Hosting Architecture:} Frontend deployed on Vercel CDN; Backend hosted on Render; Database on TiDB Cloud.
\end{itemize}

\section{4. Core University Business Logic \& Integrity Rules}
\begin{enumerate}[noitemsep]
    \item \textbf{Non-Negative Stock Rule:} Inventory cannot be issued or written off beyond current physical stock. Enforced via pre-commit transactional checks returning HTTP 400.
    \item \textbf{Sanctioned Procurement Gate:} Purchase Orders strictly require an approved indent (\texttt{status == "APPROVED"}). PO creation automatically transitions the indent to \texttt{ORDERED}.
    \item \textbf{Goods Receipt Note (GRN):} Line-by-line partial delivery tracking (\texttt{OPEN} $\rightarrow$ \texttt{PARTIAL} $\rightarrow$ \texttt{RECEIVED}). Receipt immediately increments physical stock and updates catalog price to latest purchase rate.
    \item \textbf{Director Condemnation Gate:} Proposing a write-off does not alter inventory. Stock deduction and ledger entry occur strictly upon Director approval.
    \item \textbf{Cold-Start Resilience:} Frontend client includes health ping detection to notify users during Render standby wakeups without throwing unhandled exceptions.
\end{enumerate}
